# Changelog

All notable changes to the library. Versions before 1.0.0 may change the exported API in a minor
version; a breaking change is called out as such. The history before 0.1.0 is that of the package
`internal/escp` of [terraform-provider-tplinkeasysmart](https://github.com/davidlukac/terraform-provider-tplinkeasysmart),
whose commits this repository keeps.

## 0.10.1

- **Behavior changes** (no API change: `make apidiff` shows none; no migration table is needed, nothing a program compiles against breaks). The two fixes below change what a caller can observe in a rare case, and the fake switch changes in two ways a test can notice:
  - A request that does not fit the 16-bit wire lengths is refused with an error that matches `ErrInvalid`, where it used to be sent with a wrapped length (#228).
  - A call canceled or closed during the drain of an attempt no longer writes that attempt (#234).
  - `escptest`: the fake no longer sends an answer whose lengths do not fit the wire (a scripted value over 64 KiB), as no switch could; the client hears nothing and reports no reply (#231). The fake refuses a System-page SET that carries some but not all of the device description, the DHCP flag, the address, the mask and the gateway, with error code 3 and changes nothing, as the switch does (measured, see Documentation); it only affects a test that builds such a SET by hand, because the client never does (#240).
- **Fixed:**
  - A request whose lengths do not fit the wire was sent with a wrapped length. `wire.Marshal` writes the length of each TLV value and of the whole packet in 16 bits and has no error result, so a value of 64 KiB or more, or a packet that large, went out with a length that did not match its bytes (or failed in the operating system). The one entry every request passes, `Client.send`, now checks first: such a request is refused with `ErrInvalid` (the error names the TLV type or the packet and the sizes, never a value), before the socket is drained, before a sequence number is used and before anything is written, so the client is as it was and the next call works. The largest value and packet that fit are sent as before. The only public way to reach it is a very long `Config.Username` or `Config.Password`, which every write that carries credentials sends; everything else a request holds is validated short. A management write refused for its size is not treated as a lost reply: there is nothing to settle (#228, #231).
  - A call canceled or closed during the drain of an attempt still wrote that attempt. `send` empties the socket before each request; since 0.10.0 the drain ends when the call's context ends, but `send` did not look at the context again, so a call canceled (or closed with `Close`) in that window, about 1 ms per attempt, wrote its request and then returned `context.Canceled` or `ErrClosed`, never `*UnconfirmedWriteError`, although a write may have been applied: a caller that read "canceled" as "nothing was sent" was wrong. `send` now looks at the context after the drain and before the sequence number is used, so a call canceled or closed in the drain sends nothing, like one canceled before an attempt. The error is the same as before. The window is not new (before 0.10.0 the drain ignored the context altogether); it was found by the pre-release review of 0.10.0 (#234, #236).
- **Documentation:**
  - `PROTOCOL.md`, `docs/writing-safely.md` and the doc comments of `SetHostname` and `writeSystem` state, with the measurement (firmware 20250710), that the System-page SET is all-or-nothing: a SET with the device description, the address and the mask, and without the DHCP flag, is refused with error code 3 and changes nothing, and so is one without the gateway; the full set of five is accepted. A SET with the device description alone was not tried. This is why `SetHostname` re-sends the address settings as discovery reported them, and why it stays declared cosmetic: no argument of the call can change them (#235).
  - The adversarial checklist has a fifth probe: mutate by hand what the two mutation runs cannot see, the expression of a `case` clause and the changed lines after the first gap of a multi-line diff hunk (#238).
  - `CONTRIBUTING.md` and the catalog describe the new checks below; `docs/architecture.md` lists `internal/seams`; `RELEASING.md` asks for `scripts/seams` before the tag (#226, #229, #230, #233).
- **Tests and tooling** (no API change; the contributors and the CI see these):
  - `validatecall`, an analyzer of `make lint`: an exported function of the root package that takes a value of a type with a `Validate` method calls it, or a helper that does, or says why not in a `// validatecall:` comment. New tests find every writer by what it calls and not by its name (`TestEveryExportedClientMethodIsInTheSettingsTableOrNamed`, `TestEveryExportedClientMethodThatReachesTheSendPathIsAWriterOfTheTable`) and fail for a writer with an argument and no row in the refused-argument table (`TestEveryWriterWithAnArgumentHasARefusedArgumentRow`); the table has five new rows (`SetPVIDs`, `SetHostname`, `SetIPConfig`, `SetVLANMode`, `DeleteDot1QVLAN`) (#226).
  - `nosleep`, a second analyzer: no `time.Sleep`, and in a test no `time.After` that is a guess of how long something takes, without a `// nosleep:` reason; `make lint` runs it a second time with the `live` tag. A `forbidigo` rule keeps `SetReadDeadline` to `transport.go` and `discover.go`. The tests that guessed (the close, outcome, transport, leak, registry and parked-pair tests) wait for an event or look at the state again through the helpers of `await_test.go`; the slow-fragment test advances a clock the test controls, which `recv` now reads through the client's clock seam (`c.now()`, as the drain does; the same behavior when a test sets no seam). `TestReadModifyWriteCallsDoNotUndoEachOther`, which waited 300 ms, is removed: the last row of `TestReadModifyWritePairsKeepBothChanges` is the same case without the guess (#229). The one pause left in the helpers is the 1 ms poll interval of a condition wait, bounded by the failure of the test (#239).
  - `gosec` G115 (integer conversion) applies to the wire and model paths and the readers and parsers of the root package again, where it was off for the whole module; the conversions that are bit-level by design carry a `//nolint:gosec` with their reason, and the writers that convert a value their own `Validate` has just bounded are listed in `.golangci.yml` (#227). The two conversions of `Marshal` point at the check that bounds them (#231).
  - `TestWritersSendOnlyWhatTheirRowSays` drives every writer against the fake and holds the TLV types of each accepted SET to the impact class of its row of the settings table; `TestTheWriterRowsMatchTheSettingsTable` keeps the two tables it uses complete. `SetHostname` is named there as re-sending what discovery reported, and the test holds those bytes to what `Info` reported (#232).
  - `TestEveryIdentifierTheDocsNameExists` fails, with file and line, when a Markdown document or a Go comment names an exported identifier of the module that no longer exists (an exemption is `stalenames: <reason>`); its first run found two stale sentences in the catalog, now reworded (#233).
  - `scripts/seams FROM TO` (`internal/seams`) lists the exported symbols whose behavior changed in a range, the ones that call a changed helper and, with `-provider`, which of them a consumer uses, plus the files touched by more than one commit: the seams to test the provider against before a tag (#230).
  - `make mutation-extended` runs the operators gremlins leaves off by default (`PKG=<directory>` limits any mutation target to one directory); the weekly workflow runs it as a job of its own, informational, with no threshold and a summary of the survivors (#225).
  - Tests of the two fixes: a table over the limits of the lengths, one for the largest packet that is still sent, one for a management write refused for its size, a fuzz target (`FuzzMarshalAfterCheckLengths`) and a test of the fake's reply bound (#231); a test that drives the drain through the `datagramConn` seam with a clock the test controls and shows a canceled and a closed call sending nothing (#236). The fake refuses a partial System-page SET, and every System-page writer is held to send all five settings (#240).

## 0.10.0

- **Behavior changes**, from issue #216: the text and JSON decoders of the input types apply their `Validate`, so a file or a snapshot that holds a value a writer would refuse is refused when it is decoded, not when it is written. The exported surface only grows (`make apidiff` lists 14 added methods and nothing removed); the break is in what decoding accepts, which `make apidiff` cannot see. Each row is one change; the number is the issue.

  | 0.9.0 | 0.10.0 |
  |---|---|
  | `PortID`, `LAGID`, `VLANID`, `PortVLANID`, `Priority`, `Kbps`, `Hostname` and `VLANName` had no text or JSON decoder of their own, so any number or text decoded; only `Validate` (and so the writer) refused it. A configuration or a snapshot with port 33, VLAN 4095, a rate of 100 kbps or a device description with a space decoded without an error (#216) | Decoding applies `Validate` and refuses what it refuses, with an error that matches `ErrInvalid` and the same message; a map key too. A text that is no number in its canonical spelling is refused the way `ParsePortID` refuses it (`"+3"`, `"03"`, `" 3"`, `"3.0"`). A refusal leaves the receiver as it was, and a JSON `null` leaves it alone. The zero value still reads (`0` or empty text, "not set"), and so do the values a switch reports (`Speed` `link-down`, `VLANMode` `none`); the writers and `Validate` of a record still refuse a zero where one is required. A JSON number must be an integer literal (`-0` is refused; `3.0` and `1e1` were refused before). A JSON string that holds the canonical number also reads (`"3"`), which a struct field refused before; it is how a map key arrives before Go 1.27 (from Go 1.27 a key goes to `UnmarshalText`; both apply the same rule). A value outside the rules that a reply carried, such as a port number above 32 from a faulty reply, still encodes but no longer decodes. The cross-field checks of a record (`Mirror`, `LAG`, `PortConfig`) stay in its `Validate`: decode, then call `Validate` before writing, as before |
  | `Speed.UnmarshalText` and `VLANMode.UnmarshalText` refused the empty text, so the zero `Port`, `PortConfig`, `PortStats` and `VLANModeSetting` did not read back from their own JSON (#216) | The empty text is the zero value (`Validate` still refuses it as a setting) |
  | The error of `Hostname.Validate` and `VLANName.Validate` quoted the whole value, and the "is not a port number" error of `ParsePortID` the whole text, so a 4 MB value gave a 4 MB message (#216) | An error quotes at most 40 bytes of the value, cut at a rune boundary, and then says `... (N bytes)` with the full length; the message of a value of 40 bytes or less is unchanged |

- **Added:** `UnmarshalText` and `UnmarshalJSON` on `model.PortID`, `model.LAGID`, `model.VLANID`, `model.PortVLANID`, `model.Priority` and `model.Kbps`, and `UnmarshalText` on `model.Hostname` and `model.VLANName` (14 methods, #216). The encoders did not change: a value still encodes as its number or its text.
- **Fixed:**
  - The drain that empties the client's socket before each request took a timeout for "nothing is waiting" even when the read had not waited: a goroutine held up for more than 1 ms between setting the read deadline and the read got an immediate timeout while a datagram was queued, and that datagram, left from an earlier request, could be read as the answer to the request just sent (it is only accepted when its sequence number matches, so the window is narrow, but it exists for any program on a loaded machine). A timeout now ends the drain only if the read was seen to wait at least half of the 1 ms; otherwise it reads again, within the existing bound of 64 datagrams, so a flood still ends. The drain also ends when the call's context ends (`Close`, a cancellation), and a read error that is only ICMP noise (`ECONNREFUSED`, the Windows `WSAECONNRESET`) no longer ends it. The window is narrowed, not closed: a hold-up between the clock read and the poller's own check is not seen; a read that never consults a deadline would close it (#207, #210).
- **Documentation:** the defect catalog (`docs/defect-classes.md`: the common `DC-C` and library `DC-L` classes with, for each, the question to ask before code, the test it needs, the check that watches for it and the probe that breaks it, a routing table, and the new class DC-L09, an emptiness check that is itself a timed read) and the adversarial review checklist (`docs/adversarial-review.md`); `CONTRIBUTING.md` asks to route a change by the catalog, and the pull request template asks a fix to name its class (#187); the catalog says which analyzers and checks exist, and which five proposed checks are declined and why (#202, #215). The decoders are documented where the encoders are: the sentences about what decoding accepts, the zero value and round trips are in `README.md`, `model/doc.go`, `docs/architecture.md` and `docs/errors.md` (an `ErrInvalid` is also what a refused decode matches), and the DC-L05 entry names the test that holds the rule and the lesson that library behavior can differ across the supported Go versions (the map key above) (#216, #223).
- **Tests and tooling** (no API change; the contributors and the CI see these):
  - Tests of the decoders: a table test and a fuzz target with a committed corpus for each group (`FuzzNumericDecoders`, `FuzzDecodeStrings`), each refusal test failing against a lenient decoder; `TestTheZeroValueOfEveryRecordSurvivesJSON` round-trips the zero value of every exported record of `model` and fails when a record is neither covered nor listed with its reason (`Operation` and `WriteMethod`, whose empty `Method` has no name) (#216). `TestDecodersAgreeWithValidate` compares the decoder and `Validate` of each of the 13 scalar types of `model` that have both, over values below, at and above each limit and in every form a decoder is reached by (text, JSON string, JSON number, map key): a decoder reads a value exactly when `Validate` accepts it, or it is the zero value, or it is one of the two values a switch reports (`Speed` `link-down`, `VLANMode` `none`); `TestEveryScalarTypeWithAValidateHasADecoderInTheTableOrAnExemption` fails for a new scalar type with a `Validate` and no decoder (#216, #223).
  - The tests that pin the documented guarantees carry a `// guarantee: <Name>` marker (a marker may name the package it pins, `model.WriteGate`), and `make lint` fails for an exported identifier whose doc comment promises something and that has no marked test, and for a marker that names nothing: 36 identifiers, 36 marked (#203). `make catalogcheck` (in `make lint`) fails when a check named in the catalog does not exist, or an entry, anchor or link is wrong (#191, #205).
  - Two analyzers in `devtools/analyzers`, run by `make lint`: `readwrite` (a read of a setting followed by a write outside the modify guard) and `lockwait` (a blocking wait while a lock is held; the 13 critical sections of the client that wait on purpose carry a `// lockwait:` reason) (#188). 29 more linters are enabled, with import rules for the layers (`model` imports only the standard library and the internal wire and invalid packages, `safety` only `model`, nothing outside `escptest` and the examples imports the fake) and a rule that only `transport.go`, `discover.go` and `escptest` write a datagram; the two `time.After` calls became stopped timers (#189).
  - CI: `make modcheck` (`go mod tidy -diff`, `go mod verify`) and `make actionlint` run in the build job, no checkout keeps its credentials except the two jobs that push the badges branch, and `release.yml` is read-only except the job that publishes (#192); the weekly soak runs three legs, idle, with `GOMAXPROCS=1` and under CPU load, from one program (`internal/soak`) that `make soak`, `soak-idle`, `soak-single`, `soak-loaded` and the workflow share (#214); a `canary` job builds and tests the provider's `main` against the change on every pull request, informational, with a verdict that says whether the change or the provider is red (#220).
  - Tests: fuzz targets for the parsers that had none (`FuzzParserBounds`, `FuzzReplyPayload`, `FuzzInfoFromTLVs`, `FuzzAssembleConfig`, and targets in `model`, `internal/wire` and `safety`) and a test that fails for a parser without one (#193); a snapshot of what a zero `Config` resolves to and of the package budgets, and a test that every method of `Client` that takes a context ends with it and with `Close` (#190); the stale-datagram tests put the datagrams in front of the client's socket through the `datagramConn` seam and assert that none is waiting when the request goes out, instead of sending them from a second socket and hoping they had arrived, which failed under CPU load on macOS (#206, #213); the drain has its own table test over the seam, with a clock the test controls and no sleeping (#210); the text checks read the files git tracks, so an ignored local file no longer fails them (#186); the copied `devtools` do not name a script outside this repository (#204).
  - Every read-modify-write method has a parked-pair test: `TestReadModifyWritePairsKeepBothChanges` holds each of the six methods that call `beginModify` between its read and its write, completes a second call, releases the first and asserts that both changes are in the switch (nine pairs, including the lost update of #141), and `TestEveryReadModifyWriteMethodHasAParkedPairTest` fails by name for a method that has no pair (#222).

## 0.9.0

- **Breaking changes and behavior changes**, from the audit round of November 2026 (a full review of the library by independent readers, then a second review of the fixes together). `make apidiff` suggests this version. Each row is one change; the number is the issue.

  | 0.8.0 | 0.9.0 |
  |---|---|
  | `Close` ended the client until its next call, which opened it again (a closed client reopened its socket and claim, and `ConfigBackup` on one panicked) (#135, #139) | `Close` ends a client **for good**: every later call returns `ErrClosed` and sends nothing; make a new client with `Dial`. The zero `Client` is closed too (`ErrClosed`, no panic; a nil pointer still panics) (#161) |
  | `Close` waited for the call in flight (seconds to minutes at the defaults) and for the calls queued behind it, which then reopened the client (#161) | `Close` ends the call in flight and the waits that hold the client's lock (the lease wait of `EnableDHCP`, the move wait of `SetIPConfig`, the settle after a lost reply, the lookup by MAC) at once; the cut-short call returns `ErrClosed` (joined with `ErrMoveUnconfirmed` when a management write may have been applied); queued calls give up with `ErrClosed` (#161, #181) |
  | A write that got no reply was reported as `ErrNoReply`, as if it had not been applied, and a management write was sent again after a new session key (up to twice `Retries+1` sends) (#149) | It returns `*UnconfirmedWriteError` (matches `ErrWriteUnconfirmed` and, as before, `ErrNoReply`): the write may have been applied. A write of impact management is not repeated after a new session key; it first proves that the switch still knows the session with one authenticated read, so a management write costs one extra read (#149, #183). `docs/writing-safely.md` says what to do with the outcome |
  | A client made with `Host` and `Config.MAC` looked the switch up by its MAC when the address stopped answering and followed it to whatever address it answered from (#144) | It keeps to the address unless `Config.RelocateByMAC` is set (a client with only a MAC still finds its switch by it; `SetIPConfig` and `EnableDHCP` follow their own switch whatever this says). The address a lookup returns is checked before the client follows it (a unicast IPv4 address that names one device) |
  | A client made with an address only never claimed the MAC its switch reported, and a client made with a MAC only had no address key: two clients of one switch both worked (#151) | The claim is renewed after every reply (the MAC of the first contact, the address after a move); a key another client holds gives `ErrSwitchInUse` to that call and every later one, and a refused client sends nothing (it used to send its key exchange, which replaced the owner's session). The refusal is mutual (#151, #181). Use one client per switch |
  | `SetIPConfig` canceled after the gate and before its write got the lock was probed and reported as `ErrMoveUnconfirmed`; a probe that proved "not applied" still matched `ErrWriteUnconfirmed` (#181, #183) | Nothing was sent, so the call returns the cancellation; a settled outcome matches `ErrNoReply` only, `ErrWriteUnconfirmed` and `ErrMoveUnconfirmed` stay for outcomes that are unknown |
  | `SetPortPriorities` with an empty list sent a full rewrite of every priority that changed nothing (#169) | It returns `ErrInvalid`: the call is a patch ("change these ports"), and an empty one names nothing to change. (An empty collection that the caller owns, a port set of a group, still clears it) |
  | `IPConfig.Validate` (and so `SetIPConfig`) accepted addresses in 0.0.0.0/8, 240.0.0.0/4 and 169.254.0.0/16, which no host that follows the usual rules can reach (#163) | They are refused (`ErrInvalid`) |
  | `model.Firmware` had an exported `Build` field next to the unexported string it is read from (#167) | `fw.Build` becomes the method `fw.BuildDate()` |
  | `SetVLANMode` told a write gate that it names the MTU uplink port, or no port, so `safety.PortGate` waved through a change that isolates every port (#165) | `model.Operation.AllPorts` is set for every VLAN mode change and `PortGate` treats it as naming every port: it refuses while any port has a link or is in a LAG, which on any switch you can reach is always. A front end that offers the write uses `MaxImpact` and its own confirmation |

- **Added:** `ErrClosed` (#139), `ErrWriteUnconfirmed` and `*UnconfirmedWriteError` (#149), `Config.RelocateByMAC` (#144), `model.Operation.AllPorts` (#165), `model.Firmware.BuildDate` (#167). **Removed:** `model.Firmware.Build` (see the table).
- **Fixed:**
  - Read-modify-write calls undid each other when they ran at once (`SetHostname` could revert a `SetIPConfig`, two `SetPortPriorities` lost one change): they are one step now (`SetHostname`, `SetIPConfig`, `EnableDHCP`, `SetPortPriorities`, and the checks of `SetBandwidth` and `SetStormControl` against each other) (#141, #183).
  - A `FirmwareGate` shared by clients of several switches held its lock while it read a firmware version, so a silent switch stalled the writes to the others (#153).
  - A first reply without a MAC address became the identity of the switch, after which any device that answered was accepted (#155).
  - A fragmented reply had one timeout per packet and no packet cap: `ConfigBackup` is bounded by one deadline per attempt and 64 packets (#157).
  - The lookup of a client by MAC probed the real network on the default ports even for a client pointed at a fake: it follows the client's `SwitchPort`, `HostPort` and `BroadcastAddr` (#159).
  - After a `SetIPConfig` move the host MAC of the request header is refreshed, as it is after a lease (#181).
  - `escptest` gives its ports back when the test or the fake ends, so `-count=n` and long soaks no longer run out of them (#171).
- **Documentation:** the guides match the model split, the one-client rule and the code; the Go blocks of the README and `docs/` are compiled by a test; the 20230218 compatibility row says exactly what was verified on that build and what was not (#175, #179).
- **Tests and tooling:** the nine mutants that timed out are killed (#133); the default claim of `Dial` is tested (#146); the session key, the settle conditions and the session reset after a move are tested (#173); a flaky registry test waits for nothing it does not need (#137); `release.yml` can be re-run for a tag from before `examples/consumer` (#176).

## 0.8.0

- **Breaking changes**, made together before 1.0: the values and their rules move out of the client into package `model`, and four behaviors that were accepted before are refused now. `make apidiff` suggests this version.

  | 0.7.0 | 0.8.0 |
  |---|---|
  | The values (`PortID`, `PortSet`, `MAC`, `VLANID`, `Speed`, `Impact`, `Firmware`, the setting records such as `PortConfig`, `LAG`, `Dot1QVLAN`, `QoS`, their `Validate` methods, limits, parsers and constants), `Operation`, `WriteGate` and `Reader` were declared in package `escp`, beside the client and the transport (#113) | they are declared in **`github.com/davidlukac/escp-go/model`**, a package that imports nothing of the client, with its own page on pkg.go.dev. There are no aliases: a half-moved API would keep two spellings of every name |
  | `PortSetFromMask(v []byte)` returned a `PortSet` and did not check the length: a slice of any length was read as a mask (#106) | `model.ParsePortMask(v []byte) (PortSet, error)` refuses input that is not exactly four bytes, with an error that matches `ErrInvalid`.   | `Operation.Name` was a `string` and the settings table named its methods with strings, so a misspelled name was a different, unknown operation (#111) | `Operation.Name` is a `model.Method`, with a constant for every read and write (`model.MethodSetPort`, ...), `Validate`, `ParseMethod` and text encoding. An untyped string constant still assigns to it, a string variable needs `model.Method(s)`, and a name that is not a method is refused by `Validate`. `Method.Operation().On(ports).Replacing(group)` builds the operation a gate is asked about |
  | `Config.Validate` accepted any `Timeout`: `time.Hour` with ten retries holds a call for a day when a switch stays silent (#107) | a `Timeout` above **`MaxTimeout` (30 s)** is refused by `Config.Validate` and `Dial` with an error that matches `ErrInvalid`. Zero still selects the default |
  | A client that knew its switch's MAC (`Config.MAC`, or the one of its first contact) accepted a reply that carried no MAC at all, so a device that answered without one could take the session over (#108).   | `safety.FirmwareGate` remembered one verified build per gate, so a gate shared by clients of two switches, or a switch replaced under the same address, was judged by the first one it saw (#109) | the verdict is kept **per MAC address**: `model.Reader` has a new method **`SwitchMAC() model.MAC`** (the zero value means unknown, and the firmware is then checked on every write instead of remembered), and `Client.SwitchMAC()` is added. **A type that implements `Reader` itself adds the method** |
  | Any number of `Client`s could talk to one switch in one process; the switch keeps one session, so they failed each other with timeouts and rejected writes (#115) | a second `Dial` of the same switch in one process fails at once with **`ErrSwitchInUse`**: the switch is named by its MAC address and by its address and port, a claim is taken for both or for neither, and `Close` releases it. A client that was closed and calls again takes its claim again, or fails with `ErrSwitchInUse` when another client has taken the switch since. - **`escptest` and `safety`:** `escptest.Switch.SetMAC`, `DefaultMAC`, `PortSetting` and `EnableModel` take and return `model.MAC` and `model.PortID` instead of `[6]byte` and `int` (a plain value converts: `model.MAC(b)`); the types in `safety` are the `model` types (`WriteGate`, `Operation`, `Impact`, `Firmware`, `PortSet`, `BuildDate`, ...), so a gate written for 0.7.0 changes only its import.
- **Added:** `ErrSwitchInUse` (#115), `MaxTimeout` (#107), `Client.SwitchMAC` and `Reader.SwitchMAC` (#109), `model.ParsePortMask` (#106), `model.Method` with its constants (#111).
- **Internal** (no API change beyond the above): the pin, the learned MAC and the wrong-device state are one `identity` collaborator with its own lock, the two loops that wait for a moved switch or a DHCP lease share one `pollUntil`, and `Client.SwitchMAC` never waits for a call in flight. The planned `session` and `mover` collaborators were not extracted: they would share the client's lock, socket and in-flight request, so a type would only pass the same state around (#112). `VLANID` is declared with the other 802.1Q types (#110).
- **Tests:** the flaky-test hunt found one cause, a port the kernel had just released and handed to another socket on macOS; the fake's test ports now come from 20000-28999, below the range the kernel uses for its own sockets, and nothing else reproduced in more than 25 shuffled runs with the race detector, under `GOMAXPROCS=1` and under CPU contention (#114).
