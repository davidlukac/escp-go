### escp: a Go client for TP-Link Easy Smart switches

escp talks the switches' native UDP management protocol (ESCP), as spoken by the vendor's configuration utility. It reads and writes the settings of a TL-SG108E v6, finds switches on the network, validates every value before anything is sent, and ships the safety gates and a fake switch that a front end needs to use it responsibly. It is the library behind the Terraform provider for these switches, and is written to be reused by a command line client and by other programs.

Status: version 0. The API may change in any minor version until 1.0; CHANGELOG.md lists every change (see also the stability section of the package documentation). Which hardware and firmware it was verified on is in the compatibility table; the wire format is in PROTOCOL.md.

The switch is real network equipment with no console. A wrong write can cut the management path or the uplink, and recovery is a physical factory reset. Read Writing safely before the first write.

Install

go get github.com/davidlukac/escp-go

import "github.com/davidlukac/escp-go"       // package escp
import "github.com/davidlukac/escp-go/safety" // write gates and the compatibility table

Go 1.26 or later. The module has one dependency, golang.org/x/sys (to share the reply port). It is tested on Linux, macOS and Windows against a fake switch; FreeBSD builds. On a system without a port-sharing option only one client per host works at a time. Pin an exact version while the module is 0.x (see the stability note above).

Read-only runnable example, which lists the switches on the network (and the ports of one when ESCP_HOST, ESCP_USERNAME and ESCP_PASSWORD are set): examples/discover.

Quick start

c, err := escp.Dial(escp.Config{Host: "192.0.2.11", Username: "admin", Password: escp.Password(pw)})
if err != nil { /* ... */ }
defer c.Close()

info, err := c.Info(ctx)     // model, firmware, MAC, address: no credentials needed
ports, err := c.Ports(ctx)   // reads cannot change the switch
for _, p := range ports {
	fmt.Printf("port %d: %s (configured %s)\n", p.ID, p.ActualSpeed, p.ConfiguredSpeed)
}

Dial sends nothing and binds no socket; the first call does the key exchange.

A Client is safe for concurrent use but sends one request at a time, because the switch answers one at a time. Use one Client per switch. Clients for different switches work side by side; two for the same switch fail (the switch keeps one session).

Every method takes a context.Context. Cancelling it stops the call, and nothing is written once it is done.

Discover(ctx, DiscoverOptions{}) finds the switches on the local network without credentials or addresses.

Finding a switch by MAC address

A switch's address can change; its MAC address does not. Put it in the configuration and the client pins the identity and finds the switch when it has to:

mac, _ := escp.ParseMAC("00:00:5e:00:53:01") // escp.MAC: a comparable value, the zero value means "no MAC"
c, err := escp.Dial(escp.Config{MAC: mac, Username: user, Password: pw}) // no Host: found by discovery on the first request

With Config.MAC set, a device that answers with another MAC is refused (ErrWrongSwitch, naming both) and nothing is written to it. The MAC is checked on every reply, the key exchange's included.

With no Host, or a Host that stops answering, the client looks the switch up by its MAC (a discovery probe that stops at the first reply from that switch, normally under a second; ErrNotFound when nobody answers, after a second try of the lookup, because one right after a management move once missed a switch that was there). escp.Locate(ctx, mac, opts) is the same lookup for a front end.

Dial still sends nothing; the lookup happens on the first request.

Writing safely

Every write follows the same steps: the arguments are validated and a bad value is refused before anything is sent (errors.Is(err, escp.ErrInvalid)); the optional write gate is asked; the write is sent with the credentials; a refusal by the switch is a *RejectedError.

c, err := escp.Dial(escp.Config{
	Host: host, Username: user, Password: pw,
	WriteGate: safety.Chain(
		safety.FirmwareGate(),               // only firmware builds this client was verified against
		safety.MaxImpact(escp.ImpactTraffic), // nothing that can cut the management path
		safety.PortGate(),                    // only ports with no link and no LAG
	),
})
err = c.SetPort(ctx, escp.PortConfig{ID: 3, Enabled: true, Speed: escp.SpeedAuto})
var refused *safety.PortUseError
if errors.As(err, &refused) { /* the gate refused; nothing was sent */ }

A gate sees the Operation (the method, the ports it names, its Impact) and returns an error to refuse. Gates are plain functions: write your own, or combine with safety.Chain.

Impact is the worst the method can do with any arguments: ImpactCosmetic (LED, device description), ImpactTraffic (port settings, rate limits, storm control, QoS, IGMP, mirroring, VLAN groups) or ImpactManagement (the IP settings, the VLAN mode, PVIDs, link aggregation, loop prevention).

safety.NewDryRun() records the operations a command would perform and sends none of them; it still needs a reachable switch, because some writers read first.

The client does not know which ports carry traffic and, apart from SetIPConfig, does not read back after a write. Deciding whether a write is prudent (safety.UseOf says what a port is used for) and verifying the result are the caller's job.

Restoring is explicit. There is no "reset": to put a setting back, write the value you recorded.

Data structures

Ports are numbers from 1: a PortID for one, a PortSet for a set (a comparable value held as the wire bitmap: no duplicates, ascending, Union/Minus/Intersect, escp.NewPortSet(2, 3) refuses a port outside 1 to MaxPort). A record that is a port has ID (Port, PortConfig, PortStats); a record that refers to a port has Port (PortBandwidth, PortStorm, PortPVID, PortPriority); a port with a role is named for it (MTUVLAN.UplinkPort, Mirror.MirrorPort).

Closed sets are types with String, Parse..., Valid and a list function: Speed (ConfigurableSpeeds), QoSMode (QoSModes), Priority (1 to 4, as the web UI shows it), VLANMode (VLANModes). The spellings are the web UI's and the Terraform provider's; consumers keep them in saved state, so they do not change.

Readers return values, not pointers. Counters in PortStats are the switch's 32-bit counters and wrap.

Limits and validators are public so a front end can refuse a bad value before it reaches the client: PortID.Validate, VLANID.Validate, Kbps.Validate, VLANName.Validate, Hostname.Validate, ValidateLAG, ValidateIPConfig, and the constants they use (MaxPort, RateStepKbps, MaxBandwidthKbps, LAGGroupCount, ...).

Testing against a fake switch

escptest starts a UDP server on a loopback port that speaks the protocol (RSA key exchange, RC4, TLVs, fragments) and can misbehave on request (dropped packets, a mute switch, a switch that leaves after an address change, a broken backup). It is the same fake the library's own tests use.

func TestMyCode(t *testing.T) {
	f := escptest.Start(t)
	f.EnableModel(map[int]escptest.LinkSpeed{1: escptest.Link1000Full}) // a stateful switch that enforces the measured rules
	c, _ := escp.Dial(escp.Config{Host: "127.0.0.1", SwitchPort: f.Port(), HostPort: escptest.FreeUDPPort(t),
		BroadcastAddr: escptest.Loopback, Username: escptest.Username, Password: escptest.Password})
	// ... use c, then ask f what it received: f.WriteCount(), f.AllSets()
}

SwitchPort, HostPort and BroadcastAddr exist only for this; a real switch always uses 29808 and 29809.

Logging

Config.Logger and DiscoverOptions.Logger take a *slog.Logger; the library logs nowhere else, and nil discards. You own the format, destination and level, so the library's lines look like the rest of your logs:

logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelDebug}))
client, err := escp.Dial(escp.Config{ /* ... */ Logger: logger.With("request_id", id)})

Identification. Every line carries component=escp (the logger name of other frameworks); filter on it to keep or drop the library's lines. A client also attaches host and mac.

Context fields. What you attach with Logger.With comes along on every line. Every message is logged with the call's context (...Context methods), so a handler can add what lives there (trace id, tenant): the mapped diagnostic context of log4j and friends.

Levels are slog's four. Debug is the protocol (each request and reply: operation, sequence number, TLV types and sizes, never values), Info the lifecycle (session, lookup by MAC, writes), Warn a recoverable anomaly (lost packet, repeated download). Error is not used: failures are returned. Handlers for zap, zerolog and logr exist (zapslog, logr.FromSlogHandler and their kin) if your program does not use slog.

Attribute names are the contract (lower snake case, one meaning each). New ones can be added in any release, for example for hardware with PoE; none is renamed or removed before a major version. Message texts may change.

No message carries the password, user name or session key. The Terraform provider routes the logger to tflog. A forbidigo lint rule keeps fmt.Print* and log.* out of the package.

Security

ESCP has no real secrecy: the password travels in every write, protected only by RC4 with a key exchanged under a 64-bit RSA key that anyone who can capture the traffic can break. Use it on a network you trust, never log a Config, and do not reuse the switch password elsewhere.

Package escp is a client for the TP-Link Easy Smart UDP management protocol (ESCP), as
spoken by TL-SG108E v6 switches. It reads and writes the switch's settings, finds
switches on the network and validates every value before anything is sent. The wire
format is described in PROTOCOL.md at the root of the repository.

Stability ¶

The module is version 0: until a 1.0 release, exported names, types and error values may
change in any minor version, and every change is listed in CHANGELOG.md. Where something
outside the code depends on a spelling (the names of Speed and QoSMode values are kept in
saved state by the Terraform provider), the doc comment of that name says so.

Naming ¶

A field that holds a port number is named for what the record is. A record that is a
port (Port, PortConfig, PortStats) calls it ID; a record that refers to a port (PortBandwidth,
PortStorm, StormConfig, PortPVID, PortPriority) calls it Port; a port with a role in
the record is named for the role (MTUVLAN.UplinkPort, Mirror.MirrorPort). Readers are
named for what they return (Ports, QoS, LED, Dot1Q), writers Set... and Delete....

Layout of the package ¶

A setting is one file: its types, its reader, its writer, its parser and its validation live
together, and its tests sit in the file of the same name with the suffix _test (ports.go,
ports_test.go). The settings are leaves: they depend on the client and on the shared
helpers, never on each other (except Port, the type most of them refer to).

Settings: ports, lag, qos, bandwidth, storm, igmp, mirror, loopprevention, led, system,
stats, backup, vlan_mtu, vlan_port, vlan_mode, vlan_8021q (the reads) and
vlan_8021q_write. system.go is the device description, ip.go the static management address
(SetIPConfig and its lost-reply handling) and dhcp.go the lease (EnableDHCP).

The client: client.go (Client, Dial, Close, the socket), config.go (Config, WriteGate,
InfoReader, Info), info.go (reading Info), session.go (the key exchange and its retry),
transport.go (packets, encryption, sending, receiving, fragments, deadlines), request.go
(the one place that sends a gated SET and a GET, and the port count) and errors.go.

Shared: mac.go (MAC, the one place a switch's hardware address is parsed, compared and printed), operation.go (the Operation a gate sees and the Impact classes), limits.go (the
public limits and Validate functions), portset.go (PortID and PortSet: the port numbers and the sets of them, which are the wire bitmap) and discover.go (finding
switches without credentials).

Sub-packages hold what has a boundary of its own: internal/wire (the packet codec, the
session crypto and every TLV type number, which no caller needs), internal/udp (sharing the
reply port between sockets), safety (the policy gates and the compatibility table) and
escptest (a fake switch for tests). Tests are named for the source they exercise; the ones
that cut across sources have a name of their own: cancel_test (cancellation), parsers_test,
readers_test, identity_test (identity and lookup by MAC address), write_gate_test, dryrun_test, fake_switch_test (the fake itself) and
helpers_test. CONTRIBUTING.md at the root of the repository is the checklist for adding or
changing a setting.

Identity: finding a switch by MAC address ¶

A switch's address can change (a lease, a move), its MAC address does not. Config.MAC names the
switch: it pins the identity, so a request to an address that now belongs to another device
fails with ErrWrongSwitch before a session is handed to it or a write is sent (the MAC is
checked on every reply, the key exchange's included), and it lets the client find the
switch when Config.Host is empty or stops answering (Locate does the lookup: a discovery probe
that stops at the first reply from that switch, normally under a second; a lookup that finds
nobody is tried once more before ErrNotFound is returned). Nothing is sent by
Dial. A device that takes over the address meanwhile ignores requests encrypted with a session
key it never accepted; the client then starts a new session, and the reply to the key exchange
names the stranger, so nothing is written to it.

Using a client ¶

Dial prepares a Client for one switch; nothing is sent to it until the first call.
Reads (Ports, Dot1Q, QoS and the rest; named for what they return) cannot change the
switch. Writes are the methods named Set... and Delete...:

c, err := escp.Dial(escp.Config{Host: "192.0.2.11", Username: "admin", Password: escp.Password(pw)})
if err != nil { ... }
defer c.Close()
ports, err := c.Ports(ctx)

A Client is safe for concurrent use, but it sends one request at a time because the
switch answers one request at a time. Use one Client per switch and share it between
goroutines. Clients for different switches work side by side, in one process or on one
host: switches always reply to UDP port 29809, the clients share that port, and each
keeps only the replies from its own switch. Two Clients for the same switch do not work
at all (measured: 30 reads out of 30 failed, and the switch dropped pings meanwhile).
The switch appears to keep a single session, so that each key exchange invalidates the
other client's. Discover can run next to a Client. Port sharing was observed on macOS with
real switches, and a test shows that on Linux a broadcast reaches every sharing socket; where
the system offers no sharing option the second bind fails with an error.

Discover finds the switches on the network without credentials and without knowing
their addresses.

Writing safely ¶

The switch is real network equipment with no console: a wrong write can cut the
management path or the uplink, and recovery is a physical factory reset. Every write
therefore follows the same steps:

The arguments are validated (see the Validate functions) and a bad value is refused
before any write is sent. A writer that names a port also reads the switch's port count
once (the first time), to refuse ports the switch does not have: that is a read, and it
happens before the gate.

The Config.WriteGate, if there is one, is consulted with the write's Operation (the
method, the ports it names and its Impact class). When it refuses, the method returns
the gate's error unchanged and sends no write. The safety package provides gates
for firmware builds this client was not verified against, for a ceiling on the impact,
for the ports a write touches, and for a dry run, and Chain combines them.

The write is sent with the credentials, which ride on every SET. If the switch
answers with a non-zero code the error is a *RejectedError (it matches ErrRejected).

The client does not know which ports carry traffic, and apart from SetIPConfig (which
waits for the switch to answer at its new address) no write reads back to check that it
took effect. Deciding whether a write is prudent (is the port in use? is it in a link
aggregation group?) and verifying the result are the caller's job. The doc comment of
each write says what it can disturb, and the safety package answers the common question
of what a port is used for. A few writes read the current settings first so they can
send the rest unchanged (SetHostname, SetPortPriorities); their comments say so. Every write
that names a port also refuses ports the switch does not have (ErrInvalid): the client reads
the switch's port count once, on the first such write, and keeps it.

Errors ¶

Test errors with errors.Is and errors.As, never by message: ErrNoReply (the switch did
not answer in time), ErrRejected and *RejectedError (the switch refused a write),
ErrNoInterface (Discover has nowhere to send), ErrMoveUnconfirmed (SetIPConfig lost
track of the switch), ErrInvalidConfig (a configuration backup that is not complete, after the download was repeated) and
ErrInvalid (an argument refused before any write was sent; the message names the value and
what is allowed), ErrReplyTooLarge (a fragmented reply bigger than any switch sends).

Logging ¶

The library writes nowhere on its own. Pass a *slog.Logger in Config.Logger (a Client) or
DiscoverOptions.Logger (Discover, Locate) and it reports through that; nil discards everything.
The caller owns format, destination and level, so the lines look like the rest of the caller's
logs: a JSON handler gives JSON, a handler bridging to zap, zerolog or logr gives theirs.

Every line carries component=escp, which identifies the library the way a logger name does;
filter on it to keep or drop the library's lines. The switch a client talks to is attached to
its lines as host and mac, so several clients in one log can be told apart. Fields the caller
attached with Logger.With (a request id, a tenant) come along on every line, and every message
is logged with the context of the call (slog's ...Context methods), so a handler can add what
lives in the context, such as a trace id: that is the mapped diagnostic context of other
frameworks.

The levels are slog's four. Debug lines are the protocol (each request and reply with the
operation, sequence number, TLV types and sizes, and each fragment), Info lines the lifecycle (a
session, the switch located by MAC, a write with its operation and impact, a lease), Warn lines
a recoverable anomaly (no reply and a retry, a session reopened, a download repeated). Error is
not used: failures are returned, not logged. TLV values are never logged, so no message carries
the password, the user name or the session key.

Attribute names are the contract: lower case, snake_case, one meaning each. New names may be
added in any release (a setting the hardware of a later model has, such as PoE, brings its own);
an existing name is not renamed or removed before a major version. Message texts may change.

Security ¶

ESCP has no real secrecy. The password travels in every write, protected only by RC4
with a key exchanged under a 64-bit RSA key, which anyone who can capture the traffic
can break. Use it on a network you trust, and never log a Config.

      type Client ¶

type Client struct {
	// contains filtered or unexported fields

Client talks ESCP to one switch. It is safe for concurrent use; requests

      func Dial ¶

      func (*Client) ConfigBackup ¶

func (c *Client) ConfigBackup(ctx context.Context) (ConfigFile, error)

ConfigBackup downloads the switch's binary configuration file (the same
bytes as System Tools > Backup Config in the web UI). The vendor utility
requests it with an authenticated SET carrying an empty TLV 768; the file
arrives in fragments, which are reassembled. Nothing on the switch changes. Although it is
a SET on the wire, it is a read: it never passes the write gate, so it works on any firmware
(as the provider promises for reads) even where writes are refused.

The result is complete or there is none. The replies are UDP: one can be lost, and the
fragments carry no index, total or checksum (the web UI is different: TCP, with a declared
Content-Length). A download is therefore accepted only when it is structurally complete (it
starts with the magic, the last fragment arrived, the packets before it are equally long, see
assembleConfig) and a second download, requested separately, is byte for byte the same. Anything
else is repeated, up to Config.Retries+1 rounds, and then reported as ErrInvalidConfig. A
configuration that changes while it is read fails the same way. A rejection, a missing reply
and a cancelled context end the call at once.

      func (*Client) EnableDHCP ¶

func (c *Client) EnableDHCP(ctx context.Context) error

EnableDHCP makes the switch lease its management address from a DHCP server. It does nothing when
the switch already leases one.

DANGER: this moves the switch to an address the server chooses, which this client cannot know in
advance, so the call needs Config.MAC (otherwise ErrInvalid): the client looks the switch up by it
until discovery reports the DHCP flag on with a usable address, then follows it, so later calls on
this client go to the leased address. The switch is silent for a moment while it asks for the
lease (measured: about two seconds), and it ignores a static address written while it leases
one, so SetIPConfig is the way back.

The write may be applied without a reply. When it got none and the lookup finds the switch static
at its old address, the error says the write was not applied (it matches ErrNoReply); when nothing
can be established the error matches ErrMoveUnconfirmed and the caller must look for the switch by its
MAC before it believes anything. Callers must guard: a network without a DHCP server leaves the
switch without an address, and the way back then needs this host to be on the address the switch
falls back to.

Example ¶

Let the switch lease its address. The leased address is not known in advance, so the client must
have the switch's MAC: it looks the switch up by it and follows it to the lease.

package main

import (
	"context"
	"fmt"
	"os"

	"github.com/davidlukac/escp-go"
)

func main() {
	mac, _ := escp.ParseMAC("00:00:5e:00:53:01")
	c, err := escp.Dial(escp.Config{MAC: mac, Username: "admin", Password: escp.Password(os.Getenv("SWITCH_PASSWORD"))})
	if err != nil {
		fmt.Println(err)
		return
	}
	defer c.Close()
	if err := c.EnableDHCP(context.Background()); err != nil {
		fmt.Println("DHCP not confirmed:", err) // ErrMoveUnconfirmed: look for the switch by its MAC before anything else
		return
	}
	// The way back is SetIPConfig with the static address: it writes the DHCP flag off.
}

      func (*Client) SetIPConfig ¶

func (c *Client) SetIPConfig(ctx context.Context, cfg IPConfig) error

SetIPConfig gives the switch a static management address, keeping the device description as
the switch reports it. It turns DHCP off: a switch that leases its address ignores a static
one written next to the flag (measured on switch 03, firmware 20250710), so the flag is
written off with the address, and the switch is at that address a fraction of a second later.

DANGER: this moves the switch. The request is answered from the old or the
new address, so the client accepts replies from both and, once the switch
confirms, follows it: later calls on this client go to the new address.

A switch that applies the write may never answer it from the old address, so
when the write gets no reply the client probes both addresses and compares
what answers with what was asked and with what was there before (by MAC
address, so a different device does not count). The outcomes: the switch
has the new settings, and the call succeeds as if the reply had arrived; the
switch is unchanged after all the attempts went unanswered, and the error says the
write was not applied (it matches ErrNoReply); or nothing can be established, and the
error matches ErrMoveUnconfirmed. In that last case the state is unknown and the caller
must look at both addresses before it believes either. The same holds when ctx is
cancelled or expires after the write was sent: the probe still runs (for a bounded
time), because "cancelled" would not say whether the switch moved; a probe that still
shows the old settings then proves little (the write may be taking effect), so it is
reported as ErrMoveUnconfirmed, not as "not applied". A write the switch refuses, or the gate refuses, is not probed:
nothing was applied.

Callers must guard: a wrong address, mask or gateway can cut the management path for good.
EnableDHCP is the way back to a lease.

      func (*Client) SetLAG ¶

func (c *Client) SetLAG(ctx context.Context, group LAGID, ports PortSet) error

SetLAG creates or replaces a link aggregation group: TLV 4608 with the group
id and the member port mask. An empty port set removes the group. Group
and ports are checked against ValidateLAG first. The switch itself refuses
ports that conflict with mirroring, a port-based VLAN, a bandwidth limit or
storm control, and member ports that differ in speed, negotiation, flow control,
enabled state or (in port-based QoS mode) QoS priority, or that are half duplex;
such a refusal comes back as a *RejectedError that names the conflict. The switch
checks these only when the group is written: it does not keep members alike
afterwards (see SetPort). Changing a group whose ports carry traffic can cut the
uplink; callers must guard against that.

type Config struct {
	// Host is the switch's IPv4 address or hostname. It is required unless MAC is set, in which
	// case the address is found by discovery on the first request.
	Host string
	// MAC, when set, pins the identity of the switch: a device that answers with another MAC
	// address is never written to (the request fails with ErrWrongSwitch). With no Host, or when
	// Host does not answer, the switch is looked up by MAC with a discovery probe on the first
	// request and again when it stops answering (its address may have changed); nothing is sent
	// by Dial.
	MAC MAC
	// Username and Password are sent with every write and every authenticated read.
	Username string
	Password Password
	Timeout  time.Duration // how long to wait for a reply per attempt, default 3s
	// Retries is the number of additional attempts after the first when the switch stays
	// silent: zero selects the default (2), NoRetries (any negative value) selects none.
	// One request is therefore sent up to Retries+1 times, each waiting up to Timeout. A call
	// that needs a session makes up to four such requests (the key exchange and the request,
	// then both again if the switch stops answering mid-call), plus the discovery that learns
	// the switch's MAC on a client's first call: with the defaults 36 seconds, 45 on the first.
	Retries int

	// (29809). A real switch always replies to 29809 whatever port the request came from,
	// so change them only to talk to a fake switch.
	SwitchPort int
	HostPort   int

	// default 255.255.255.255.
	BroadcastAddr netip.Addr

	// WriteGate, when set, is consulted before every write; see WriteGate.
	WriteGate WriteGate

	// values) at Debug, sessions, lookups and writes at Info, retries and repeated downloads
	// at Warn. Nil discards them. The library writes nowhere else, and no message carries the

      func Discover ¶

func Discover(ctx context.Context, opts DiscoverOptions) ([]Info, error)

Discover broadcasts an unauthenticated discovery probe and returns every switch that
answers within the window: one Info per MAC address, sorted by IP address, empty (not an
error) when nobody answers. It is read-only, needs no credentials and is not subject to a
WriteGate.

The probe goes to the subnet broadcast address of each interface, with that interface's
MAC as the sender, so switches behind a second network card are found too. It is sent
again halfway through the window, because UDP is lossy; duplicate replies are dropped.
If the context ends early, Discover returns the replies collected so far together with the
context's error. A failure to bind the socket, or to send on every interface, is an error.

Switches always reply to UDP port 29809 whatever the sender's port. The port is shared
(see Client), so Discover can run while a Client of the same host is working: on macOS it
found both switches three times out of three while a Client was reading at the same
time. Where the system offers no port sharing, or another program holds the port
exclusively (an old Easy Smart utility), binding fails and Discover returns that error.

Example ¶

Find the switches on the network. Run it on its own: switches reply to UDP port 29809,
which a Client or the vendor's utility on the same host would share out unpredictably.

package main

import (
	"context"
	"fmt"
	"time"

	"github.com/davidlukac/escp-go"
)

func main() {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	switches, err := escp.Discover(ctx, escp.DiscoverOptions{Window: 2 * time.Second})
	if err != nil {
		fmt.Println("discovery stopped early:", err)
	}
	for _, s := range switches {
		fmt.Println(s.IP, s.MAC, s.Model, s.Firmware)
	}
}

      func Locate ¶

      type RejectedError ¶

type RejectedError struct {
	Code   ReplyCode
	Reason string
}

RejectedError is a write the switch answered with a non-zero code. It matches

Example ¶

A write the switch refuses matches ErrRejected, and carries the reply code.

package main

	"errors"
	"fmt"

	"github.com/davidlukac/escp-go"

func main() {
	err := fmt.Errorf("creating the group: %w", &escp.RejectedError{Code: 4})

	fmt.Println(errors.Is(err, escp.ErrRejected))
	var rejected *escp.RejectedError
	if errors.As(err, &rejected) {

	}
}

      type WriteGate ¶

type WriteGate func(ctx context.Context, sw InfoReader, op Operation) error

WriteGate decides whether the client may send a write to the switch. Every
method that changes the switch (each Set* and Delete*) calls it first, with
the client itself and a description of the write (its method, the ports it
names and its Impact), and sends nothing when it returns an error: the
method returns that error unchanged. A gate may read from the switch through
sw but must never write, and must be safe for concurrent use. Reads are
never gated.

A method that sends several writes consults the gate before each of them
with the same operation, so a gate that is expensive should remember its
verdict.
